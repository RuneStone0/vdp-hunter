How the unlisted dataset is built

Zone files

ICANN's Centralized Zone Data Service hands out the authoritative name list for each gTLD: every registered domain, not a popularity ranking. Parsed in minutes, one apex name per line.

security.txt

Every apex name is asked for /.well-known/security.txt per RFC 9116. A hit is a company that has written down how to report a vulnerability, whether or not it pays a bounty.

The diff

Each pass is compared with the last. New programs, changed policies, expired files: all of it lands in the change feed, the same way the free data does.

Questions

Is a security.txt the same as a bug bounty?

No. It means the company has a disclosure process. Some pay, some only say thank you. The bounty filter separates confirmed payers from the rest, and every row shows what the file actually says.

Where does the free data come from?

The public program lists, refreshed daily, via the bounty-targets-data project. It is the same data you can collect yourself, which is why it is free.

Can I cancel?

Any time, from the same email thread that issued the key. No call, no retention offer.

Do you scan aggressively?

One request per domain per path, two paths, a documented user agent, and transport failures are retried at lower concurrency rather than hammered. Rate limits are published in the docs.
